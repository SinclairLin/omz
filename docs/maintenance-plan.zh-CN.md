## 1. 本轮确定的方向

将项目定位为个人 Zsh 配置，维护自己的使用习惯、组合方式和少量函数。目录跳转、历史搜索、解压、补全展示和输入高亮使用现成工具。

实施后的默认组合：

| 功能 | 选择 | 本轮实施范围 |
| --- | --- | --- |
| 第三方 Zsh 插件管理 | Antidote，静态加载，原生 `pin:<SHA>` 固定插件提交 | 必做 |
| 目录跳转 | 桌面与普通服务器优先 zoxide；z.lua 为明确选择的兼容后端 | 必做 |
| 历史搜索 | fzf 官方 Zsh 历史搜索；缺少 fzf 时使用 Zsh 原生搜索 | 必做 |
| Tab 补全展示 | 保留 fzf-tab，交由 Antidote 管理 | 必做 |
| 输入建议 | 保留 zsh-autosuggestions，交由 Antidote 管理 | 必做 |
| 语法高亮 | 保留 zsh-syntax-highlighting，交由 Antidote 管理 | 必做 |
| 通用解压 | ouch；保留 `extract`、`x` 作为薄封装 | 桌面默认启用 |
| 文件预览 | 文本 bat、目录 eza、图片 fzf 官方预览脚本；均有降级 | 必做 |
| 提示符 | 保留 simple 主题和现有外观，拆分 Git 状态逻辑 | 本轮保留 |
| 小工具 | 保留 randport、dcupdate，归入项目自有函数 | 必做 |
| Atuin、Starship、fast-syntax-highlighting | 作为后续独立评估项 | 不纳入本轮默认依赖 |

不新写插件下载框架、版本锁定格式、压缩格式分派表或图片渲染协议实现。Antidote 的固定提交及静态加载能力见资料 S1；其他工具能力见 S2-S5。

## 2. 当前需要解决的问题

1. `omz.zsh` 无条件加载插件，无法按环境关闭功能；环境和个人配置也晚于部分初始化操作加载。
2. `fzf-tab`、自动建议、语法高亮的仓库内副本自 2023-11-13 首次导入后没有更新；语法高亮版本为 `0.8.0-alpha2-dev`。
3. `z.lua` 在 2026-03-25 已更新到文件自报的 1.8.25，不能把它当作失去维护的软件。替换它主要是减少桌面依赖、统一交互，而非修复“废弃项目”。
4. `config/fzf.zsh` 自己实现历史去重和 ZLE 缓冲区回填，并覆盖用户的 `FZF_DEFAULT_OPTS`。
5. `lib/img_preview.sh` 依赖 FIFO、缓存光标位置及长时间休眠，退出时执行 `killall ueberzug`；仓库中未找到 `get_cursor.sh` 的调用入口。
6. 历史、查询记录、上次目录与配置源码放在同一个 `cache/` 下。
7. 安装器同时存在包管理器及 `~/.fzf` 更新路径；缺少统一的版本归属规则。
8. 当前测试以非交互加载和局部配置断言为主，不能验证实际按键、补全、高亮或图片位置。

上述均为本仓库调查结果；上游当前能力以文末资料为依据。

## 3. 支持范围与默认配置

### 3.1 三种配置档

| 配置档 | 适用场景 | 默认组合 |
| --- | --- | --- |
| `desktop` | macOS；主动选择该配置的 Linux 桌面 | zoxide、fzf、三个 Zsh 插件、ouch、bat；eza 可选；图片按能力开启 |
| `server` | 普通 Linux、SSH 工作环境 | zoxide、fzf、三个 Zsh 插件；ouch、bat、eza 可选；关闭图片预览 |
| `minimal` | OpenWrt、存储或内存受限环境 | Zsh 原生补全和历史、simple 主题、自有函数；增强工具按需安装 |

`OMZ_PROFILE=auto` 的确定规则：OpenWrt 为 `minimal`，macOS 为 `desktop`，其他系统为 `server`。Linux 桌面可以显式设为 `desktop`。

缺失可选依赖时采用下面的降级链，不在 Shell 启动时下载或安装：

- 目录跳转：`auto` 选择已安装的 zoxide，否则使用已安装且有 Lua 的 z.lua，否则只保留 `cd`。
- 历史搜索：fzf 不可用或版本不满足时，回退 Zsh 原生 `Ctrl-R`。
- Tab 补全：fzf-tab 或 fzf 不可用时，回退 Zsh compsys。
- 文本预览：`bat`、`batcat`、限行纯文本。
- 目录预览：eza、系统 ls。
- 图片预览：官方脚本与终端能力匹配时显示图片，否则显示文件类型、尺寸等可获得的信息。
- ouch 缺失时不注册 `extract`、`x`；诊断命令明确提示如何启用。

显式选择某个不可用后端时给出一次清晰提示并保留基础 Shell；不得偷偷切换成行为不同的后端。

### 3.2 平台承诺

- macOS 14+ Apple Silicon 与 Ubuntu 为本轮自动化主验收平台。
- Intel Mac、Debian、Arch 的安装路径继续维护，按实际 CI 或真机验证结果标注保证范围。
- OpenWrt 保留 `apk`、`opkg` 两条安装路径。未进行真机验收前，文档明确标注“安装流程测试通过，运行体验待真机验证”。
- OpenWrt 不自动源码编译 Rust 工具；没有匹配包或预编译产物时保留轻量功能。
- 暂定 Zsh 5.8+ 为增强配置测试目标。依赖最低版本由所选上游版本的要求与实际矩阵共同确定。
- zoxide 的交互选择按当前上游文档要求 fzf 0.51.0+；新的增强配置不继续沿用现有 fzf 0.30.0 门槛。旧版 fzf 可以降级，不宣称全功能支持。

## 5. 配置接口与加载顺序

### 5.1 配置接口

个人配置只增加少量需要选择的开关：

```zsh
OMZ_PROFILE=auto
OMZ_JUMP=auto                 # auto | zoxide | zlua | none
OMZ_HISTORY_SEARCH=auto       # auto | fzf | native
OMZ_IMAGE_PREVIEW=auto        # auto | off
OMZ_RESTORE_DIRECTORY=false
```

三个插件通过 `config/plugins.txt` 声明，个人禁用需求使用一个 `OMZ_DISABLED_PLUGINS` 数组，不为每个插件再增加布尔变量。禁用只影响加载，不触发下载或清理。

终端标题继续兼容 `_OMZ_APPLY_PREEXEC_HOOK`、`_OMZ_APPLY_PRECMD_TITLE_HOOK` 的原有意义，不为它们重复增加新开关。迁移期将 `_OMZ_APPLY_CHPWD_HOOK` 映射到 `OMZ_RESTORE_DIRECTORY`，将 `_OMZ_APPLY_HISTORYBYFZF=false` 映射到原生历史搜索；显式的新选项优先。无对应历史值时，恢复上次目录默认关闭。

当前 `config/env-self.zsh` 在新个人配置缺失时继续读取，且移到初始化前；新文件存在时只读取新文件，避免执行两次。迁移器提供复制选项，默认保留旧文件。

### 5.2 加载顺序

1. 解析仓库路径、XDG 目录和基础环境，设置默认选项，再读取个人覆盖。
2. 非交互 Shell 到此返回，只保留环境设置；不运行 ZLE、提示符、目录恢复和插件初始化。
3. 交互 Shell 加载历史、基础快捷键、自有函数，设置补全目录及 `zstyle`。
4. 初始化 compinit，将缓存放到用户缓存目录；若外部环境已完成初始化则复用，不能重复初始化。
5. 初始化 fzf 官方集成及所选跳转后端。
6. 加载项目别名、终端标题钩子和 simple 主题。
7. 加载 Antidote 生成的静态文件，顺序为 fzf-tab、自动建议、语法高亮。

后续步骤不得再次覆盖 Tab 或 `Ctrl-R`；所有包装 widgets 的插件均在项目按键配置完成后加载。官方 fzf 集成不能替代 fzf-tab 的补全展示职责。

重复 `source` 必须跳过已完成的交互初始化，避免重复注册钩子、重复包装 widgets；选项变更通过新开 Shell 生效。

## 6. 依赖与插件管理

### 6.1 插件固定方式

`config/plugins.txt` 使用 Antidote 原生清单，按加载顺序包含：

- `Aloxaf/fzf-tab`
- `zsh-users/zsh-autosuggestions`
- `zsh-users/zsh-syntax-highlighting`
- 仅在选择兼容后端时需要的 `skywind3000/z.lua`，采用仅克隆的声明，初始化由项目适配。

实施时为每项写入经过验收的完整 `pin:<SHA>`。Antidote 本身的来源与完整提交放在 `config/bootstrap.zsh`，通过 Git 获取指定提交；不默认跟随主分支。

具体 SHA 在第一阶段选定、测试后写入，不在规划中猜测版本号。所选 Antidote 提交必须实测支持 `pin:`，不能假设所有历史发行版均有该功能。

`scripts/manage-plugins.zsh` 仅提供项目操作入口：

- `install`：按固定提交安装所需插件并生成静态加载文件。
- `build`：根据现有本地依赖重新生成加载文件，不隐式更新版本。
- `verify`：核对本地依赖提交与清单是否一致。

插件检出、缓存等工作交给 Antidote。启用配置档与个人禁用项由入口传给它，不再实现通用插件管理器。运行时只读取已经生成的文件；配置变化或缓存缺失时提示执行上述入口。

静态加载文件记录对应配置档和清单标识，避免把 desktop 结果错误用于 minimal。文件含本机绝对路径，因此迁移目录后重新生成。

### 6.2 版本更新流程

1. 手动选择一个上游版本或提交。
2. 修改清单中的 SHA，在临时数据、缓存目录中安装并验收。
3. 通过后重新生成日常使用的加载文件。
4. 在 `docs/verification.md` 记录提交、平台和实际测试结果。
5. 形成独立 Git 提交，便于回退。

固定提交的插件不会依靠一次普通 `antidote update` 自动升级；必须更新清单。Shell 启动过程中不联网、不自动更新，也不调用包管理器。

### 6.3 二进制工具的归属

- macOS 使用 Homebrew 管理 fzf、fd、zoxide、ouch、bat；eza 按需安装。
- Linux 优先使用发行版包。版本不满足时先报告能力缺失；使用上游产物必须是明确选择，并验证版本、架构和校验值。
- 不覆盖已经存在的 `~/.fzf`，不在每次安装中自动 `git pull`，不自动执行其安装器修改其他配置。
- Antidote 只负责 Zsh 插件，不再同时管理一份 fzf 二进制。
- Lua 仅在选择 z.lua 后端时安装，不作为所有环境的必需依赖。
- fd 缺失时保留 find 降级；已有 `fd`、`fdfind` 探测继续使用，不额外写入全局软链接。
- 修正 Arch 路径中的单独同步数据库行为，不继续使用 `pacman -Sy` 后安装软件的流程；采用符合完整升级要求的明确安装指引或流程。

## 7. 各功能的迁移契约

### 7.1 z.lua -> zoxide

- 保留 `z <关键词>` 的入口，但在迁移文档中说明排序和匹配语义可能不同。
- 新的标准交互入口为 `zi`；`zz`、`zf` 映射到交互选择，保留这两个常用别名。
- `zb`、`zc`、`zbi`、`zbf`、`zh`、`zzc` 不强行模拟。依赖这些语义的用户选择 `OMZ_JUMP=zlua`，保留原有快捷操作。
- z.lua 后端继续支持用户已有 `_ZL_*` 配置，不和 zoxide 同时注册记录目录的钩子。
- 导入先备份两个后端的数据，再使用所选 zoxide 版本的官方导入接口。读取 `_ZL_DATA`，未设置时使用旧工具默认位置。
- 上游当前文档给出 `zoxide import z.lua`；实施时以实际固定版本的 `import --help` 为准，覆盖自定义数据路径，不照搬其他版本的命令语法。
- 导入是安装或迁移步骤，不能放进每次 Shell 启动；失败不启用完成标记，不删除旧数据库。
- 升级已有安装时，完成数据导入或明确选择不导入后，再切换默认后端。不能只因新安装了 zoxide 就提前改变旧用户的跳转行为。

### 7.2 手写历史搜索 -> fzf 官方集成

- 删除 `historybyfzf` 和自维护的 `history | awk` 管道。
- `Ctrl-R` 由 fzf 官方历史组件单独负责；选择后回填命令行，取消选择保留原缓冲区。
- Tab 由 fzf-tab 负责，不让另一套补全配置在其后覆盖 Tab。
- 现有上下方向键按前缀查找、按词移动等习惯继续保留。
- 对较老版本 fzf，只有安装包提供并经过验证的官方独立脚本才可加载；否则回退原生搜索。
- 用户的 `FZF_DEFAULT_OPTS` 保留；项目视觉默认值在其前面组合，使用户覆盖有明确优先级。历史、文件选择和 Tab 的专有参数各自设置。
- 删除无人消费的 `FZF_PREVIEW_COMMAND`，改为对实际使用方配置预览。

### 7.3 extract -> ouch

保留接口 `extract [-r|--remove] <文件...>` 及别名 `x`，封装只处理参数、输出目录和成功后的删除动作。

明确行为：

- 每个输入单独提取到同目录下的 `<完整文件名>.extracted/`，例如 `a.tar.gz.extracted/`。这是有意调整，需在迁移文档列出。
- 目标目录已存在则报错，不自动混入既有目录。
- 只有该文件解压成功且用户传入 `-r` 时才删除对应原包；多文件中任一失败，整体返回非零状态。
- 成功与失败都不改变调用者工作目录。
- 不重新维护按扩展名调用不同程序的 case 表。
- 原脚本 `.deb`、`.rpm` 的 control/data 特殊展开不再作为通用接口承诺；迁移文档列出对应平台原生工具。
- ouch 版本和构建的实际格式覆盖通过测试确认，尤其是 rar；不把某个构建缺失的支持写成全平台保证。

### 7.4 图片与文件预览

- 保留 `lib/file_preview.sh` 作为薄适配层，统一做路径传递和能力选择。
- 优先从已安装 fzf 包定位官方 `fzf-preview.sh`；找不到时保留文本及目录预览，图片显示说明。
- 不因系统是 macOS 就假定使用 Kitty；终端和 tmux 环境必须分别验证。
- 图片展示不启动项目自管常驻进程，不使用 `killall` 清理其他窗口的进程。
- 删除 `lib/img_preview.sh`、`lib/get_cursor.sh` 及光标缓存依赖，前提是新路径已验收。
- 文本限制读取行数；目录限制展示规模；空格、中文、前导连字符等路径按普通文件名正确处理。

### 7.5 小函数与提示符

- randport 迁入 `functions/randport.zsh`。文档明确其结果是当时探测为空闲，不构成端口预留；缺少探测工具时清晰失败。
- dcupdate 默认改为 `docker compose pull && docker compose up -d`，取消无条件 down。相关服务重建仍可能中断，不承诺零停机。
- simple 主题保持现有颜色和信息结构；Git 状态函数迁到 `lib/git-prompt.zsh`，不趁本轮增加更多状态项。
- 保留用户主动配置的 EDITOR、PATH、SSH 包装及 Git 快捷命令；可选命令不存在时不注册明显不可用的别名。
- 终端标题只在交互环境注册，正确处理 SSH 和不支持相关序列的终端。

## 8. 用户数据迁移与回滚

迁移由 `scripts/migrate-state.zsh` 显式执行，不在日常启动里悄悄合并文件。

1. 先报告旧位置、目标位置及文件是否存在；安装器支持只预览迁移。
2. 等旧配置会话结束并写入历史后，再迁移历史。仍有旧会话写入时不能宣布历史迁移已完整结束。
3. 备份 `.zshrc`、个人配置、旧状态文件和跳转数据库，记录仓库提交及外部插件固定提交。
4. 目标历史不存在或为空时复制旧历史，保留扩展历史格式；目标已有记录时停止自动导入，列出人工合并入口，不覆盖任何一边。
5. fzf 查询记录与 Zsh 命令历史分开迁移；上次目录作为纯文本读取，不 source 状态文件。
6. 所有迁移步骤可重复执行，完成标记只在校验成功后写入。旧数据在验收前保留。
7. 回滚时回到该阶段之前的配置提交，恢复对应插件清单并重新生成加载文件；恢复 `.zshrc` 前检查用户是否又编辑过。
8. 回滚与依赖清理不删除新产生的历史、跳转记录及个人配置。需要清理旧源码副本时，先确认备份及验收完成。

实施默认在 `main`，每个阶段独立提交；不使用 `reset --hard`，不覆盖用户已有未提交修改。本轮只新增方案，不执行提交。

## 9. 实施阶段与交付物

| 阶段 | 具体改动 | 完成条件 |
| --- | --- | --- |
| M0 基线 | 记录命令入口、依赖版本、现有功能和性能；验证可恢复备份 | 基线报告及迁移清单可核对 |
| M1 初始化与数据路径 | 拆分必要职责；个人配置提前读取；交互保护、配置档、XDG 路径及迁移入口 | 非交互安静、重复 source 幂等、旧数据无损；暂时保留现有后端 |
| M2 插件外移 | 选定 Antidote 和插件 SHA；生成静态加载；支持安装、构建和核对 | 固定提交一致、运行时不联网、断网仍能使用已安装插件 |
| M3 交互替换 | zoxide 后端、fzf 官方历史、加载顺序、旧别名迁移 | 三类历史/补全组件不抢按键；z.lua 兼容档可用 |
| M4 解压与预览 | ouch 薄封装、官方图片预览适配、自有函数整理 | 解压失败不删原包、不改变 cwd；图片流程不遗留后台任务 |

## 10. 验收标准

### 10.1 自动化检查

扩展现有 `tests/test_installer.sh`、`tests/test_runtime.zsh`，只对关键行为补测试：

- 安装、升级重复执行不重复写入 source 行，不修改无关 Shell 配置。
- 三种配置档、缺少可选工具、旧 fzf 以及路径含空格均能启动。
- 非交互 Shell 仅设置环境，不输出提示、不加载交互插件、不改变 cwd。
- 重复 source 后钩子数量和按键绑定不变。
- 使用伪终端实际验证 Tab、Ctrl-R、取消搜索、多行历史和自动建议接受；不只检查函数存在。
- 迁移已有目标文件、自定义 `_ZL_DATA`、重复执行、失败重试均不会覆盖历史或丢失旧数据。
- 解压成功、失败、多输入及 `-r` 的行为符合契约。
- 插件清单与本地 SHA 一致；没有网络时已安装配置仍正常。
- 所有测试使用隔离的 HOME、XDG 和临时目录，不写入真实用户历史。

安装器继续保持可由 `/bin/sh` 启动；ShellCheck 只针对支持的 sh/bash 文件，不能把 Zsh 文件当作 Bash 处理。

### 10.2 人工交互验收

| 场景 | 要验证的行为 |
| --- | --- |
| macOS + Kitty | Tab、历史搜索、高亮、自动建议、中文及空格路径、图片预览 |
| 普通终端 | 没有图片协议也能使用补全和文本预览 |
| SSH / tmux | 标题、远端路径、图片降级，无启动卡顿或异常控制字符 |
| OpenWrt minimal | 安装后的首次及后续启动、原生补全/历史、缺工具提示和资源消耗 |
| 旧配置升级 | 历史数量与代表性记录、跳转记录、个人开关、回滚后仍能工作 |

CI 初期沿用当前 Ubuntu 与 macOS 矩阵，并补上三种配置档的行为测试。Arch、Debian、OpenWrt 按可获得的真实环境逐项扩充；模拟 uname、OSTYPE 或包管理器不等于平台运行验收。

### 10.3 性能与清理

- 同机器、同版本、同目录、同环境变量，分别记录首启和稳定启动，稳定启动至少 20 次，报告中位数及 P95。
- 增强配置稳定启动中位数的回归预算为 `max(基线的 10%, 20ms)`；minimal 不应承担未启用插件的初始化成本。此为验收目标，不是现有测量结果。
- 2026-10-27 用户在 M3 实施中调整上述要求：“忽略性能，只要不是太离谱就没事”。因此旧预算保留作历史参考，不再作为后续交付门槛；发现明显卡顿或异常开销仍需处理。
- 普通目录和大型 Git 仓库分别测量提示符响应，不能仅测空目录。
- 不承诺引入新工具一定更快；报告包含功能收益与实际开销。
- 测试生成物自动清理；项目中不留下构建缓存、下载压缩包、图片 FIFO、临时截图或测试历史。
- 依赖缓存与用户状态保留在约定的用户目录，不能被普通“清理项目”删除。

## 11. 完成定义

只有 M0-M5 的自动化与已承诺平台验收完成，才称“维护改造完成”。没有 OpenWrt 真机或其他平台环境时，完成报告明确列出未验收项，不把其隐含在“全部通过”中。

最终应得到：

- 一套明确的默认工具组合和 minimal 配置。
- 可重复安装、可核对版本、运行时不联网的插件加载方式。
- 无损的历史与跳转数据迁移及可执行回滚步骤。
- 不再内嵌已外移的通用插件源码。
- 一份记录真实版本、性能、平台结果与剩余限制的验证报告。
